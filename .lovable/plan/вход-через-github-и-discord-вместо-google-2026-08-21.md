# Вход через GitHub и Discord вместо Google

## Что меняется на странице входа

- Кнопка «Войти через Google» убирается со страницы `/auth`.
- Вместо неё две кнопки: «Войти через GitHub» и «Войти через Discord» — в одном ряду на десктопе, в столбик на телефоне, с иконками и в стиле вики (неоновые границы, hover-подсветка).
- Вход по email и паролю, регистрация и сброс пароля остаются без изменений.
- Ошибки провайдера показываются тем же красным текстом, что сейчас.   
  
И ещё обязательно интструкцию как сделать это в Vercel и Supabase

## Что нужно от тебя (обязательно)

GitHub и Discord — не «управляемые» провайдеры, поэтому для них нужны свои приложения:

1. GitHub: Settings → Developer settings → OAuth Apps → New OAuth App. Получишь Client ID и Client Secret.
2. Discord: Discord Developer Portal → New Application → OAuth2. Получишь Client ID и Client Secret.
3. В оба приложения нужно вписать callback-адрес бэкенда — я дам точный URL при реализации.

После этого я сохраняю Client ID/Secret через защищённую форму секретов и включаю провайдеров в настройках авторизации бэкенда. Без этого кнопки будут выдавать ошибку «Unsupported provider».

## Технические детали

- `src/routes/auth.tsx`: убрать `signInWithGoogle` и импорт `@/integrations/lovable/index`; добавить два обработчика на `supabase.auth.signInWithOAuth({ provider: "github" | "discord", options: { redirectTo: window.location.origin } })`.
- Редирект остаётся публичным (`window.location.origin`), сессия подхватывается существующим `useAuth`; после появления сессии — переход в `/cabinet` как сейчас.
- `src/integrations/lovable/index.ts` — автогенерируемый файл, не трогаем.
- Провайдеры включаются инструментом настройки соцвхода в том же шаге, что и код, чтобы вход не падал.
- Профиль/никнейм: у OAuth-пользователей `username` может быть пустым — при первом входе подставляется имя из профиля провайдера, иначе кабинет предложит задать ник (текущее поведение профиля сохраняется).
