# Профили, репутация и выдача админки

## 1. Выдача прав администратора из админ-панели

Новый блок «Участники и права» в `/admin`:
- поиск по нику (частичное совпадение), список участников с текущей ролью;
- кнопки «Выдать админку» / «Снять админку»;
- аккаунт создателя (ник `TheHapPpyONE`) помечен как «Создатель», кнопка снятия недоступна.

Права меняются только серверной функцией, которая сначала проверяет, что вызывающий — админ.

## 2. Перманентная админка для TheHapPpyONE

- Роль `admin` выдаётся автоматически при регистрации/входе аккаунта с ником `TheHapPpyONE` (без учёта регистра).
- Снятие этой роли блокируется: попытка снять возвращает ошибку, а страховочный триггер возвращает роль обратно.
- Если такой аккаунт уже существует — роль выдаётся сразу миграцией.

## 3. Профиль участника

Расширяем `profiles`: аватар, «о себе», ссылка (например Telegram), репутация.

Кабинет `/cabinet`:
- редактирование ника, описания, ссылки и загрузка аватара;
- карточка статистики: статей опубликовано, на модерации, правок принято, комментариев, суммарные просмотры, дата регистрации;
- показ своей репутации;
- лента последней активности (статьи, правки, комментарии).

Публичная страница `/user/$username`:
- аватар, ник, роль, описание, дата регистрации, статистика;
- список опубликованных статей автора и последняя активность;
- плашка «У автора низкая репутация», если репутация ниже порога.

Ники автора в статьях и комментариях становятся ссылками на профиль.

## 4. Репутация (в стиле Reddit, без ограничений)

- Голоса «+/−» за автора на странице статьи (один голос от одного участника на автора, менять можно).
- Репутация = сумма голосов; ничего не блокирует.
- Если репутация ниже порога (например, −5), на статьях автора и в его профиле выводится предупреждение «У автора низкая репутация».
- Плашка только предупреждает: доступ к статье, комментариям и правкам не ограничивается.

## Техническая часть

База данных (одна миграция):
- `profiles`: `avatar_url`, `bio`, `link`, `reputation int not null default 0`.
- `user_reputation_votes (voter_id, target_id, value smallint check in (-1,1), unique(voter_id,target_id))` + GRANT + RLS: публичное чтение, вставка/обновление/удаление только своим `voter_id`, запрет голоса за себя. Триггер пересчитывает `profiles.reputation`.
- `user_roles`: политики INSERT/DELETE для админов (через `has_role`), защита ника создателя триггером `BEFORE DELETE/UPDATE`.
- Обновление `handle_new_user()`: автоприсвоение `admin` для ника `TheHapPpyONE`.
- Разовый `INSERT` роли `admin`, если аккаунт с этим ником уже есть.
- Политика UPDATE на `profiles` — только свои поля, `reputation` меняется только триггером.

Код:
- `src/lib/wiki.functions.ts`: `listMembers`, `setUserRole` (обе через `requireSupabaseAuth` + проверка роли админа), `getPublicProfile`, `getProfileStats`, `voteReputation`.
- Проверка «создателя» и запрет снятия роли — в `src/lib/wiki-admin.server.ts`.
- Новый роут `src/routes/user.$username.tsx` (публичный, SSR, свой `head()` с title/description/og).
- Правки: `src/routes/_authenticated/admin.tsx`, `src/routes/_authenticated/cabinet.tsx`, `src/routes/article.$slug.tsx`, компонент плашки низкой репутации.
- Аватары — в существующий бакет медиа через подписанный URL.
