## 2. Мобильная вёрстка

### 2.1 Главная обрезана справа
Фон-слой частиц и широкие блоки на главной выходят за viewport. Правки только в презентации:
- ограничить обёртку страницы `overflow-x-hidden`, слой `PixelField` сделать `inset-0` внутри этой обёртки;
- ряды с горизонтальными отступами перевести на схему `grid-cols-[minmax(0,1fr)_auto]` + `min-w-0` там, где сейчас `flex` со фиксированными элементами;
- статистику/облако категорий на мобильном сделать в одну колонку с переносом.

### 2.2 Выбор темы уходит за экран
Поповер темы в `SiteHeader` привязан к правому краю кнопки, но кнопка сама сдвинута внутри мобильной сетки. Сделать поповер на мобильном на всю ширину экрана (фиксированное позиционирование с отступами `left-3 right-3`), сохранив выпадающий вариант с `sm:` и выше.

### 2.3 Кнопки статей в админке за рамками
В `src/routes/_authenticated/admin.tsx` строка статьи — `flex flex-wrap ... justify-between`, а блок кнопок помечен `shrink-0`, поэтому не переносится. Заменить на сетку: заголовок сверху (`min-w-0 truncate`), ряд действий ниже с `flex-wrap`, кнопки без `shrink-0`, компактные размеры на мобильном. То же для строк «участники и права».

### 2.4 Редактор на телефоне
В `src/routes/_authenticated/editor.tsx`:
- панель полей в одну колонку на мобильном, липкая нижняя панель с кнопками «Сохранить / Отправить»;
- текстовое поле с увеличенной высотой (`min-h-[55vh]`), `text-base` (чтобы iOS не зумил), моноширинный шрифт;
- панель быстрых вставок Markdown (жирный, курсив, ссылка, заголовок, список, изображение) над полем с горизонтальной прокруткой;
- предпросмотр по переключателю вместо второй колонки на мобильном.

## 3. «Кнопки не работают», нет списка участников, не отправляются статьи и комментарии

Это не баг вёрстки — так ведёт себя код при отсутствии серверного ключа. Все админ-действия, отправка статьи на модерацию и комментарии проходят через `src/lib/wiki-admin.server.ts`, который использует сервисный ключ (`SUPABASE_SERVICE_ROLE_KEY`). Если его нет в окружении Vercel:
- `userHasRole()` возвращает `false` → список участников пуст, админ-кнопки молча ничего не делают;
- записи в аудит/уведомления падают → мутации обрываются без сообщения.

Что сделаем:
- добавить видимую обработку ошибок: тосты (sonner) на всех мутациях в админке, редакторе и комментариях вместо молчаливого `void`;
- явную проверку конфигурации: если сервисный ключ отсутствует, сервер возвращает понятную ошибку «бэкенд не настроен: нет SUPABASE_SERVICE_ROLE_KEY», а не пустой результат;
- проверить локально в браузере (авторизованный прогон): список участников, отправка статьи на модерацию, отправка комментария — и починить всё, что вылезет помимо ключа.
