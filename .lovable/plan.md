# Почему «Error sending confirmation email» и как это починить

Сначала важное: SMTP-ключ Brevo, который ты прислал в чате, теперь считается скомпрометированным. Его нужно удалить в Brevo (SMTP & API → SMTP keys) и создать новый. Ниже — уже с новым ключом.

## Причина

Ошибка приходит от сервиса авторизации: он не смог отдать письмо в Brevo. Код приложения тут не при чём — регистрация использует стандартный вызов, и он падает ровно на этапе отправки письма. По присланным настройкам видно две вещи, каждая из которых сама по себе ломает отправку:

1. **Адрес отправителя на gmail.com.** Brevo не даёт отправлять транзакционные письма с адресов бесплатных почтовых доменов (gmail.com, mail.ru, yandex.ru) — подтверждённый sender этого не отменяет. Нужен адрес на своём домене с верификацией домена (DKIM/DMARC-записи в Brevo → Senders, Domains & IPs).
2. **Username для SMTP.** В Brevo логин SMTP — это не «имя аккаунта», а конкретное значение из раздела SMTP & API (обычно email-логин вида `xxxxx@smtp-brevo.com`). Если там стоит имя аккаунта — авторизация на relay падает.

## Что нужно сделать тебе (на стороне сервисов)

1. В Brevo: удалить утёкший SMTP-ключ, создать новый.
2. В Brevo → Senders, Domains & IPs: добавить свой домен и пройти верификацию (записи DKIM/DMARC у регистратора). Создать sender на этом домене, например `noreply@твойдомен`.
3. В настройках авторизации бэкенда (SMTP Settings) задать:
   - Host: `smtp-relay.brevo.com`, Port: `587`
   - Username: SMTP-логин из Brevo (не имя аккаунта)
   - Password: новый SMTP-ключ
   - Sender email: адрес на верифицированном домене
   - Sender name: `REPUBLIC WIKI TEAM`
4. В настройках URL: Site URL — домен на Vercel, Redirect URLs — `https://<домен>/**` (иначе ссылка из письма приведёт на localhost).

Если своего домена пока нет — на время беты можно отключить обязательное подтверждение email, тогда регистрация работает без письма. Скажи, если нужен этот вариант.
