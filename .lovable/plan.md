# Plan: дополнить RepublicMC WIKI

## Цель
Превратить текущий прототип в полноценную вики: удобный редактор, предложения правок, поиск, категории, медиа и удобный вход.

## Что уже есть
Главная, страница статьи/новости, базовый текстовый редактор, модерация статей, комментарии, роли (admin/user), вход по email/пароль.

## Фаза 1 — Навигация и поиск
- Страница `/articles` со списком всех опубликованных материалов и фильтром по категориям.
- Страница `/category/$name` для статей одной категории.
- Страница `/search` с серверным поиском по заголовку, описанию и содержимому.
- Страница `/recent` с лентой последних изменений (новые/отредактированные статьи и правки).
- Обновить шапку: добавить ссылки на «Все статьи», «Поиск», бургер-меню для мобильных.

## Фаза 2 — Редактор и медиа
- Markdown-редактор с live-preview (синтаксис ##, -, *, ссылки, изображения).
- Загрузка обложек через Storage bucket `article-covers` (для статей и новостей).
- Вставка изображений в тело статьи через Storage bucket `article-media` + диалог загрузки.
- Галерея: несколько картинок в одной статье, рендерим сетку или карусель.
- Парсер Markdown на странице статьи (с защитой от XSS) и автоматическое оглавление по заголовкам.
- Использовать `cover_url` для OG-изображений в `head()` каждой статьи.

## Фаза 3 — Предложения правок (wiki-style)
- Новая таблица `edit_suggestions` для предложенных изменений существующих статей.
- Участник (не админ) нажимает «Предложить правку», заполняет редактор, отправляет.
- Админ в админ-панели видит список предложений, может сравнить diff и принять/отклонить.
- При принятии: обновляется статья, создаётся запись в `article_revisions`.
- При отклонении: сохраняется причина.

## Фаза 4 — Авторизация и UX
- Вход через Google OAuth (через Lovable брокер).
- Страница «Забыли пароль?» и маршрут `/reset-password` для сброса пароля.
- Подтверждение email оставить как сейчас; при необходимости можно включить auto-confirm.
- Удаление комментариев админом/автором из UI.
- Мобильное меню и мелкие UX-улучшения.
- Опционально: публичный профиль пользователя.

## Технические детали
- Storage: создать бакеты `article-covers` и `article-media`, публичные для чтения, запись только для authenticated; настроить RLS-политики.
- Миграции: таблицы `edit_suggestions` и `article_media` (или общая таблица `media`); для поиска добавить полнотекстовый индекс или использовать `or(ilike(...))` в MVP.
- Server functions: публичные для чтения (`getArticles`, `searchArticles`, `getRecentChanges`), защищённые для записи (`createSuggestion`, `approveSuggestion`, `getSignedUploadUrl`), админские для модерации.
- Client: в редакторе добавить preview и кнопку загрузки изображения; на странице статьи заменить парсер строк на `react-markdown` + `rehype-sanitize`.
- Auth: Google OAuth требует одновременной настройки провайдера в Supabase и UI-кнопки на `/auth`.
- SEO: добавить canonical, OG-изображение, description для каждого списка, категории и страницы поиска.
