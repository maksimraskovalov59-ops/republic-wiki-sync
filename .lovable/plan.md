# План: редактор, мобильная вёрстка, смена ника и профиль (без миграций БД)

## Цель
Улучшить опыт авторов и читателей вики, не добавляя новые таблицы и не меняя схему базы данных. Все фичи опираются на существующие `articles`, `profiles`, `comments`, `article_revisions` и Storage-бакеты.

## Ограничение
Никаких новых таблиц, столбцов или миграций. Разрешены только клиентские изменения, server functions на чтение/запись существующих данных и работа с уже созданными Storage-бакетами.

## Фича 1 — Удобный редактор без загрузки на сервер

- Горячие клавиши в текстовом поле:
  - `Ctrl/Cmd + B` — жирный текст (`**текст**`).
  - `Ctrl/Cmd + I` — курсив (`*текст*`).
  - `Ctrl/Cmd + K` — ссылка (`[текст](url)`).
  - `Tab` / `Shift+Tab` для списков и отступов.
- Inline-вставка изображения по URL: кнопка "Картинка" открывает небольшой диалог с полем URL, после вставки `![описание](url)` в позицию курсора.
- Split preview: режим, в котором слева редактор, справа живой рендер Markdown. На мобильных — переключатель "Редактор / Превью" вместо двух колонок.
- Sticky toolbar: панель кнопок форматирования прилипает к верху экрана при скролле на десктопе и остаётся доступной на мобильных.
- Улучшение мобильного редактора: увеличить высоту textarea, убрать горизонтальный скролл, сделать кнопки действий крупнее и удобнее для тапа.

## Фича 2 — Исправление мобильной вёрстки

- Провести аудит текущих страниц на ширине 375–430 px с помощью Playwright и DevTools.
- Устранить оставшиеся переполнения (overflow-x) на:
  - главной странице (блоки статистики, список категорий, выпадающий поиск);
  - выборе темы в шапке (dropdown не должен уходить за экран);
  - админ-панели (кнопки действий у статей не должны выходить за карточку);
  - профиле участника (шапка профиля, статистика, репутация);
  - редакторе (toolbar и поля ввода).
- Добавить `min-w-0`, `overflow-hidden`, `break-words` и корректные grid/flex треки везде, где длинный контент может раздавить layout.
- Проверить touch target: все кнопки и ссылки на мобильных не менее 44×44 px.

## Фича 3 — Смена имени пользователя в кабинете

- Добавить форму смены `username` в личном кабинете (`/cabinet`).
- Валидация:
  - 3–24 символа;
  - только латинские буквы, цифры, подчёркивание и дефис;
  - уникальность через существующую таблицу `profiles`;
  - нельзя взять имя создателя (`TheHapPpyONE`) или уже занятое.
- После успешной смены:
  - обновить `profiles.username`;
  - обновить `author_name` в статьях и комментариях этого пользователя (чтобы история не врала);
  - перенаправить на новый URL `/user/$username` и показать уведомление;
  - предупредить пользователя, что старые ссылки на профиль перестанут работать (без таблицы редиректов это не исправить).
- Защита: создатель не может сменить свой username (или любой другой пользователь не может занять его ник).

## Фича 4 — Обогащение публичного профиля

- Добавить в `/user/$username` и `/cabinet`:
  - блок "Последние комментарии" (из таблицы `comments`);
  - блок "Последние правки" (из таблицы `article_revisions`);
  - более наглядную статистику: статей, просмотров, правок, комментариев, репутация, дата регистрации.
- Для публичного профиля: показывать краткое описание "О себе", ссылку и аватар крупнее.
- Для кабинета: добавить сводку "Моя активность за 30 дней" с последними действиями.
- Визуально разделить профиль на секции: шапка с аватаром, о себе, статьи, активность, статистика.

## Технические детали

- Изменяемые файлы:
  - `src/routes/_authenticated/editor.tsx` — редактор, хоткеи, split preview, вставка URL-картинок.
  - `src/routes/_authenticated/cabinet.tsx` — смена username, улучшенная статистика и активность.
  - `src/routes/user.$username.tsx` — обогащение публичного профиля.
  - `src/routes/_authenticated/admin.tsx` — фикс мобильной вёрстки админки.
  - `src/routes/index.tsx`, `src/components/SiteHeader.tsx`, `src/styles.css` — фикс мобильной вёрстки главной и тем.
  - `src/lib/wiki.functions.ts` — новые/дополненные server functions для смены username, активности профиля, валидации.
- Storage: не используем новые загрузки, только ссылки по URL в Markdown и обложках.
- База данных: не меняется схема. Используются существующие таблицы и столбцы.
